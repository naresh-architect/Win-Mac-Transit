== 2. Leadership Narrative (Executive Summary)

*Use this when the audience is a hiring manager, a programme sponsor, or anyone deciding whether you can own technical capability-building at scale.*

As **AI Enablement Lead**, I own the technical depth of how an organisation trains engineers to build and ship GenAI systems — not a workshop series, a full curriculum architecture.

**What I built, technically:**

* A 6-week programme spanning the entire GenAI engineering stack: LLM APIs and prompt engineering → structured output and function calling → RAG pipelines with RAGAS-based evaluation → multi-agent orchestration (LangChain, AutoGen/Microsoft Agent Framework, CrewAI) → the Model Context Protocol (MCP) → production guardrails (prompt-injection defence, PII redaction, audit logging) → containerised deployment.
* Every capstone built against a real regulated-industry scenario — pharma regulatory intake, fintech AML/KYC, insurance claims, healthcare triage, digital banking, wealth management — because an engineer who can only build against a toy dataset is not client-ready.
* A final integrative capstone that forces all four technical layers to operate as *one deployed system*, evaluated by tracing a single real request end-to-end — not four disconnected demos passed off as "done."

**Why leadership should care:**

* This directly de-risks client delivery: engineers coming out of this programme have already been evaluated on the failure modes that actually show up in production — inconsistent RAG output, unbounded agent escalation, prompt injection, PII leakage — before they hit a live account.
* It shortens ramp time on regulated engagements specifically, because the domain context (compliance, audit trails, data minimisation) is trained in, not bolted on after a client complaint.
* It's built to stay current, not to calcify. When Microsoft moved AutoGen into maintenance mode and shipped Microsoft Agent Framework as its successor, I evaluated the migration — licensing, ecosystem lock-in, learning curve, enterprise-readiness — against alternatives (AG2, CrewAI, LangGraph) before deciding what the curriculum teaches going forward. That's the same judgment call a technical leader has to make when choosing a stack for a client, and I make it as a matter of course, not as a special project.

**The role I'm looking for:** one where this exact combination — deep, current GenAI technical range, plus the judgment to keep a capability current as the field moves monthly — is the job, not a side skill.
