Comparison Brief · Updated after v5.0

Two AI evaluation frameworks, one shared philosophy

Tekstac's AI-Role Capability Assessment grades human candidates building on a shared fictional system. Our Multi-Domain Agentic Evaluator grades AI-built capstone submissions using AI agents. Different evaluees, strikingly similar design principles.

01What we're comparing

Document A

Tekstac AI-Role Capability Assessment

A 3-hour hands-on case study that grades job candidates at three career altitudes, all working on one shared fictional system (Astra, an IT support assistant), with planted bugs and traps a strong performer should catch.

  • 3 altitudes: Builder → Workflow Engineer → Delivery Strategist
  • 7 shared competencies, reweighted per altitude
  • Graded by human evaluators against a rubric
  • Planted issues (P1–P9 per tier) as the discriminator
Document B

Multi-Domain Agentic Evaluator

A design for an AI agent system that grades capstone software submissions across four technology tracks, at three increasing levels of automated rigour, culminating in an integration test across all of them.

  • 3 rigour levels: Static review → Live execution → Adversarial stress-test
  • 4 domains, each with its own weighted rubric
  • Graded by AI evaluator agents, human escalation on uncertainty
  • Adversarial probes (rephrasing-bypass, privilege-escalation, anti-decomposition) as the discriminator
  • v5.0: four-band scoring thresholds + a named failure signature per domain

03Both systems shift toward governance as altitude/complexity rises

Bucketing each framework's criteria into three themes — Technical execution, Governance/Risk, and Communication — reveals the same underlying shape in both documents, even though one reweights a fixed rubric across career tiers and the other varies criteria across technology domains.

Tekstac — weight by career altitude

Same 7 competencies, rebucketed. Technical drops from 75% to 35% by the Strategist tier.

Our evaluator — weight by domain

Different criteria per domain, rebucketed. Governance rises from 0% (RAG) to 45% (MCP).

Same chart type now, so bar heights are directly comparable — but the x-axis still means something different underneath. Tekstac's three tiers are one person's possible career path — a single Builder could plausibly grow into a Strategist. Our four domains are independent tracks — a RAG submission never "becomes" an MCP submission. The shared shape (technical execution shrinking, governance/communication growing) is a real structural parallel; it just arises from progression in one document and from domain choice in the other.

Resolved, same cut points, one renamed band: the Multi-Domain Agentic Evaluator now uses the identical four bands and identical percentage cut points as Tekstac, applied the same way across all four domains so a "Pass" on the RAG track means the same thing as a "Pass" on the MCP track. The only change is cosmetic — "Strong Hire" doesn't fit a capstone context, so it's renamed "Distinction." Both documents flag these cut points as tunable defaults, not fixed law.

05Shared design principles

Trust but verify

Don't reward blind AI acceptance

Tekstac scores unvalidated AI usage lower than not using AI tools at all. As of v5.0, our evaluator has the same competency directly, not just an analogy: an AI tool usage auditor with the identical scoring rule, alongside its existing confidence-tagged findings for every other check.

Tekstac: AI Tool Usage competency, all tiers · Ours: Section 2.7 (AI tool usage auditor) + confidence-tagged findings, Section 2.3
Deliberate traps

Plant issues the naive path would miss

Tekstac's P1–P9 issues are invisible to candidates but known to evaluators. Our probers (rephrasing-bypass, privilege-escalation) deliberately try inputs a submission's team likely never tested against.

Tekstac: Planted Issues tables, all 3 tiers · Ours: Domain B/C/D Tier 3 probers, Section 6
Failure signatures

Define what "reaching above your level" looks like

Every Tekstac tier has a named "reaching up" calibration note. As of v5.0, our evaluator has the direct equivalent — a named "reaching" signature per domain — plus a separate hard-escalation rule for single dealbreakers that Tekstac has no equivalent of.

Tekstac: Calibration Note, each tier · Ours: Sections 3.11/4.9/5.9/6.10 (signatures) + Escalation/coach agent (hard rule)
Controlled environment

Fix the environment so scores are comparable

Tekstac gives every candidate an identical pre-configured VM and toolset. Our evaluator insists on one facilitator-owned grading dataset/scenario set per domain, for the same reason: without a fixed environment, scores across submissions aren't actually comparable.

07What each could borrow from the other

Adopted in v5.0 — no longer a gap

What our evaluator took from Tekstac

  • ✓ Explicit four-band pass/fail thresholds per domain — Section 2.5
  • ✓ A named "reaching" failure signature per domain, for facilitator calibration, alongside (not instead of) the hard-escalation rule — Sections 3.11, 4.9, 5.9, 6.10
  • ✓ A separately weighted "validated AI tool use" competency for learners who build their capstones with AI coding tools — Section 2.7
Still open — Tekstac is a separate, published document

What Tekstac could take from our evaluator

  • A confidence-tagged scoring model — distinguishing "verified by execution" from "inferred from the artefact" per competency, not just a single blended score
  • An explicit anti-decomposition style check — catching a candidate who gets each task's checkbox right without ever tying the pieces into one coherent system
  • A standard interface/output contract per task, the way our evaluator requires submissions expose a common function signature, to make automated pre-screening of deliverables possible before human review
